# SensiDoc 纸质/图片单据 OCR 前端交互设计方案

> **文档版本**：v1.0.0  
> **更新时间**：2026-09-10  
> **关联计划**：`plan/PAPER_OCR_TABLE_ONNX_INTEGRATION_PLAN.md`  
> **设计目标**：重塑图片与扫描件在 SensiDoc 中的阅读、比对与审计体验，解决“原图核对难、自动与手动触发权衡、表格渲染与敏感词联动”三大核心痛点。

---

## 1. 现状痛点与核心决策分析

### 1.1 核心问题推演

在传统 Office 电子文档（Word/Excel/PDF 电子层）中，文本是确定性的，用户信任度高，上传后直接渲染 Markdown 是非常自然的体验。然而引入**纸质单据翻拍件（JPG/PNG）与纯图片扫描 PDF** 后，交互语境发生了质的变化：

```text
┌───────────────────────────────────────────────────────────────────────────┐
│                    电子文档 vs 纸质单据交互特征对比                       │
├──────────────────┬───────────────────────────┬────────────────────────────┤
│ 维度             │ 现有电子文档 (Word/Excel) │ 纸质翻拍 / 扫描单据 (OCR)  │
├──────────────────┼───────────────────────────┼────────────────────────────┤
│ 1. 数据确定性    │ 100% 确定 (直接提取字符)  │ 存在置信度 (受反光/手写影响)│
│ 2. 用户心理习惯  │ 只看转换出的 Markdown     │ **必须看原图对照核实关键数**│
│ 3. 错误发现成本  │ 极低                      │ 极高 (若漏看导致漏脱敏/错脱)│
│ 4. 转换耗时期望  │ 瞬时 (<100ms)             │ 百毫秒级 (~500ms-800ms)    │
└──────────────────┴───────────────────────────┴────────────────────────────┘
```

### 1.2 三项关键产品决策

1. **原图预览功能是“绝对刚需”**：
   * 财务发票、出入库单等严肃企业场景下，用户对 OCR 结果具有强烈的“核验”天性。必须让用户**不用离开当前界面就能看到高清原图**。
2. **是否自动执行转换？—— 推荐“单张自动，批量可控”**：
   * **单张图片 / 翻拍件**：**必须默认自动转换**。因为我们采用的纯 Rust + FP32 原始模型在 4核16G 办公 PC 上的耗时仅 500ms~800ms，拖入后不到 1 秒即可完成，用户感觉是“即拖即现”的极致流畅感，不应增加额外的点击成本。
   * **多页大文件扫描 PDF（>5页）**：采用**惰性自适应流式**（先展现当前页原图并秒级转换当前页，后台队列排队转换后续页，提供“停止/全部转换”的轻量控制）。
3. **转换结果呈现形态**：
   * 必须保持与 SensiDoc 既有资产的统一性：依然产出标准的 **GFM Markdown / 兼容 HTML `<table>`**，以便无缝使用现存的敏感词高亮标注机制与大模型提取能力。

## 2. 三套全新交互设计方案

---

### 方案一：【左右分屏·双轨对照模式】（Side-by-Side Dual-Pane）

#### 2.1 核心设计哲学
* **“所见即所核”**：将中间主舞台拆分为左右对称的等高视界——左侧为**高清原图视窗**，右侧为**Markdown/HTML 渲染与敏感词高亮视窗**。
* **双向联动透视（Cross-Highlighting）**：鼠标悬停右侧表格中的某个单元格时，左侧原图对应的文本红框（BBox）同步发光聚焦；反之点击原图区域，右侧表格自动定位到对应行列。

#### 2.2 转换触发与控制
* 用户在左侧列表选中单据或拖入图片后，**全自动静默执行 OCR**。
* 左屏立即显示原图，右屏展示约 0.6 秒的骨架占位动画（Skeleton Loading），识别完毕后平滑淡入渲染好的表格。
* 顶部工具栏提供分屏模式切换：`[左右分屏] | [仅看原图] | [仅看文档]`，适应不同屏幕宽度的自由切换。

#### 2.4 优劣势与适用场景
* **优势**：比对体验最好、财务核验效率极高、双向联动直观可信，彻底解决“看不清认没认对”的顾虑。
* **劣势**：在笔记本 13 寸或 1080P 分辨率且三栏全开时，中间每栏宽度偏窄（约 350px~450px）。
* **最佳受众**：大屏显示器办公、财务做账、严肃单据审计。

### 方案二：【视界拨杆·卷帘透视模式】（Curtain Slider / Focus Pivot）

#### 2.1 核心设计哲学
* **“极简空间最大化”**：完全维持当前 SensiDoc 的单主视窗设计，不挤占页面宝贵的横向空间。
* **三态拨杆 + 卷帘透视（Curtain Slider）**：
  * 工具栏上方常驻三态分段开关：`[原图] | [卷帘比对] | [结果]`。
  * 默认处于 `[结果]` 模式，呈现标准 Markdown/HTML；
  * 当用户怀疑某个手写数字时，一键切到 `[卷帘比对]`，屏幕正中出现一根可自由左右拖动的“垂直分割滑轨（Curtain Bar）”。滑轨左边露出底层真实图片，滑轨右边露出结构化渲染表格，像透视机一样拉动对照。

#### 2.2 转换触发与控制
* **自适应自动转换**：拖入图片后自动触发后台流水线。
* 在转换中途（500ms 内），主视窗先直接显示原图，中央浮现轻量玻璃拟态转圈标签 `[正在智能提取表格结构 65%...]`，完成后平滑切换为最终表格。
* 用户有完整的“原图 vs 结果”自由查看控制权。

### 方案三：【悬浮画中画·轻量抽屉模式】（Floating PiP & Drawer Inspection）

#### 2.1 核心设计哲学
* **“默认纯净，召之即来”**：主屏保持绝对干净的 Markdown 阅读体验与大模型脱敏工作流。
* **右下角悬浮原图缩略卡（Picture-in-Picture）**：
  * 打开图片文档时，中间直接渲染解析好的表格；
  * 右下角常驻一个半透明的高清原图小窗卡片（可折叠、可拖动、点击可全屏放大放慢审查）；
  * 鼠标滑过主屏表格的任何字句，右下角画中画原图自动居中放大该行文字的原始笔迹截图（类似精准“放大镜”）。

#### 2.2 转换触发与控制
* **智能分层自动触发**：
  * 单图直通自动处理；
  * 若为超过 10 页的纯图片 PDF，在顶部提示黄色信息条：`[检测到多页扫描件(共12页)，已自动解析第1页，是否全部后台转换？] [全部转换] [仅按需浏览]`。

## 4. 推荐落地实施路线

建议采用**“演进式推进策略”**：

```text
[阶段 1: 落地方案一 (分屏对照)] ──► 先构建坚实基础
  ├── 核心：实现中间主舞台的“左右分屏”能力，支持 [原图 / 表格] 并列
  └── 机制：上传图片自动异步触发 OCR，0.6s 内完成渲染呈现
        │
        ▼
[阶段 2: 补充联动高亮 (Cross-Highlighting)] ──► 提升专业质感
  ├── 点击右侧 Markdown 单元格，左侧原图对应的文字行 BBox 红框高亮
  └── 增加 [原图] / [分屏] / [仅结果] 的一键最大化切换
        │
        ▼
[阶段 3: 进阶体验融合 (视界/卷帘扩展)] ──► 提供高级偏好
  └── 在分屏基础上，为单屏用户提供一键“卷帘对比”或“原图悬浮快速预览”快捷键
```
