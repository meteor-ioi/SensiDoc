# SensiDoc 多模型（4B + 1B/1.5B/2B）协同抽取基准评测与架构优化实施方案

> **当前分支**：`feat/dual-model-benchmark`  
> **文档归档**：`plan/DUAL_MODEL_BENCHMARK_IMPLEMENTATION_PLAN.md`  
> **核心目标**：在离线普通 4 核 16G 纯 CPU 环境下，以 `tessera-4b-q4_k_m` 为核心基底，分别与 1B（MiniCPM5-1B）、1.5B（Qwen2.5-Coder-1.5B）、2B（MiniCPM5-2B）小微模型组合，通过扩充的中英文高难度测试集，以数据驱动（Benchmark）决选出兼顾极致速度、高指令遵循、零遗漏（高召回）与零幻觉的最佳协同策略。

## 二、 基准测试集（Benchmark）深度丰富方案

针对当前测试用例篇幅过短（100~200字）、场景单一、无英文场景的问题，测试集将**从 10 篇扩充至 20 篇**，覆盖中英文各 10 篇，并设立**短篇、中篇、长难篇**篇幅梯度，引入强干扰项与长距离跨段落上下文。

### 2.1 测试集规格体系（20 份标准 Ground Truth 文档）

```text
┌────────────────────────────────────────────────────────────────────────┐
│                       SensiDoc 20 份高难度基准评测集                   │
├───────────────────────────────────┬────────────────────────────────────┤
│ 中文复杂场景 (10 份)              │ 英文 / 跨国合规场景 (10 份)        │
├───────────────────────────────────┼────────────────────────────────────┤
│ · 01 招投标多供应商比价书 (长篇)   │ · 11 Cross-Border MSA (跨国服务)   │
│ · 02 核心研发期权保密协议 (中篇)   │ · 12 Global Offer & IP Assign      │
│ · 03 跨国并购对赌与托管协议 (长篇) │ · 13 HIPAA Clinical Audit (医疗)   │
│ · 04 集团内部廉洁与行贿通报 (中篇) │ · 14 Multi-Currency Expense (报销) │
│ · 05 核心云特权密钥交接单 (短篇)   │ · 15 AWS Security RCA (安全事件)   │
│ · 06 离职人员资产清退单 (中篇)     │ · 16 Cross-Border M&A Term Sheet   │
│ · 07 政企大数据外包合同 (长篇)     │ · 17 SaaS SLA & GDPR DPO (数据合规)│
│ · 08 私人银行KYC大额资产审查(中篇) │ · 18 Whistleblower Fraud (反舞弊)  │
│ · 09 股权质押与连带担保函 (中篇)   │ · 19 AML/KYC Ultra-Wealthy (反洗钱)│
│ · 10 复杂长难句司法调解笔录 (长篇) │ · 20 OSS License Compliance (开源) │
└───────────────────────────────────┴────────────────────────────────────┘
```

### 2.2 难度维度设计（挑战小模型缺陷）

1. **篇幅跨度**：
   * **短篇（300~500 字符）**：考验即时提取精度与最低延迟；
   * **中篇（1,000~1,500 字符）**：考验上下文注意力稳定性；
   * **长篇（2,500~4,500 字符）**：强制触发分块（Chunking）与段落流水线（Pipeline），检验跨块截断与后半程漏提率。
2. **陷阱与干扰项设计**：
   * **角色易混淆**：同一个段落中出现甲方代表、乙方代表、连带保证人、见证律师，考察是否会张冠李戴；
   * **假阳性诱饵（False Positive Traps）**：公文中的示例数字（如“*例如人民币10,000元*”）、已作废的旧条款，考察是否误提；
   * **长难句跨度**：主语与宾语之间相隔 80~120 字定语从句，检验语义解析与关联能力。

## 三、 三套协同策略的数据流与协议设计

### 3.1 策略一：宽松海选提案 + 4B 靶向终审（Proposal & Judge）

```text
待审计段落 (600~800 字)
      │
      ▼
[ 小微前置模型 (1B/1.5B/2B) ] ──> 宽松 Prompt ("宁多勿漏，提取全部疑似实体及其所在原句")
      │
      ▼ 产出候选槽位流: [{"candidate": "张三", "context_sentence": "由张三全权代表甲方签署...", "suggested_field": "法定代表人"}]
      │
      ▼ (异步推送至 4B 校验队列)
[ 4B 核心终审模型 (Tessera-4B) ] ──> 二分类校验 Prompt:
      │                                "句子: '{context_sentence}' 中，'{candidate}' 是否为 '{field}'？严格回答[是/否]"
      ▼
仅 Decode 1~2 tokens ──> 过滤错误项，保留真实项
```

* **核心价值**：4B 模型计算量降低 85% 以上（无需重复阅读 800 字，无需输出复杂结构），彻底克服小模型漏提。

### 3.2 策略二：快慢车道路由（Confidence Router）

```text
待审计段落
   │
   ▼
[ 小微前置模型 (1B/1.5B/2B) ] ──> 标准结构化抽取，并在每条输出附加置信度或标记:
   │                             `{"field": "...", "text": "...", "status": "CONFIDENT | AMBIGUOUS"}`
   │
   ├── 命中 [CONFIDENT] (约 70% 确定性项) ──> [直接确认入库，零 4B 开销]
   │
   └── 命中 [AMBIGUOUS] / 段落结构复杂 ──> [4B 专家模型异步复核接管]
```

* **核心价值**：最大限度发挥小模型的高吞吐优势，仅让 4B 成为疑难特会专家。

### 3.3 策略三：Span 边界锚定 + 语义属性归因（Span Assigner）

```text
待审计段落
   │
   ▼
[ 步骤 1: 小微前置模型 (专精找词) ] ──> 识别并提取段落内所有实体 Span 池:
   │                                   `["北京华云智远...", "周建国", "186万元", "622848..."]`
   │
   ▼ (将实体池与原段落同时注入 4B)
[ 步骤 2: 4B 核心模型 (专精连线) ] ──> 连线匹配 Prompt:
   │                                   "请将以下已知实体与目标字段进行匹配归因，无关实体输出剔除"
   ▼
4B 输出极简键值映射 ──> `{"周建国": "甲方法人", "186万元": "合同总金额"}`
```

* **核心价值**：把开放自回归抽取转变为“选项连线题”，杜绝 4B 模型幻觉与小模型的指代混乱。

## 四、 四维评测指标体系

基准测试工具将自动采集并生成以下核心量化指标：

1. **提取质量指标**：
   * **宏观召回率（Macro Recall）**：$\frac{TP}{TP + FN}$，核心度量是否解决漏提；
   * **宏观精确率（Macro Precision）**：$\frac{TP}{TP + FP}$，度量误提与幻觉控制；
   * **宏观 F1-Score**：$2 \times \frac{P \times R}{P + R}$，综合平衡分。
2. **纯 CPU 性能指标**：
   * **单篇端到端平均耗时（Avg Latency ms）**；
   * **整体吞吐（Chars processed per second）**；
   * **4B 模型有效生成 Token 总量（Decode Token Count）**；
   * **CPU 平均与峰值开销（4 核占用率）**。
3. **工程稳定性指标**：
   * **输出解析成功率（Parse Success Rate）**（需达到 100%）；
   * **异常超时与重试次数**。
