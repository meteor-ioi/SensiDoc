# SensiDoc 离线信息审计与原生无损脱敏工具 — 实施方案 (v2)

> **版本**：v2.0.0  
> **定位**：企业级离线文档智能敏感信息审计与全格式纯代码原生脱敏平台。基于 `anydoc` 实现全格式文档解析，内置 `llama.cpp` 专属冷门端口（18188）与在线 API 双轨模型调度，结合纯 Rust 原生 OpenXML/ZIP 重构与老旧二进制升级转码引擎，在零外部办公套件（免 Office/WPS/LibreOffice）依赖下，实现 100% 保留排版的原生文档安全脱敏导出。

## 3. 全格式纯代码脱敏导出引擎详细设计 (v2 核心)

### 3.1 现代 DOCX 原生无损脱敏 (XML Run 跨节点消解)

DOCX 内部文本存储在 `word/document.xml` 中，Word 经常将一个完整词拆分在多个 `<w:r>` (Run) 中的 `<w:t>` 节点里：
- **挑战**：若直接做子串匹配，跨标签词汇（如 `<w:t>张</w:t></w:r><w:r><w:t>建国</w:t>`）会被切断而漏脱敏。
- **v2 核心算法**：
  1. **ZIP 流式解包**：在内存中解压 DOCX 容器，获取 `word/document.xml` 及所有页眉页脚（`word/header*.xml`, `word/footer*.xml`）；
  2. **段落级 Run 文本投影**：遍历 `<w:p>` 段落，构建连续文本字符与其所属 `<w:t>` 节点及内部字符偏移量的索引映射表；
  3. **敏感词定位与就地打码**：在投影文本中检索全部敏感项，将等长打码字符（如 `张**` 或 `***`）按字符偏移区间精准回写至对应的各 `<w:t>` 节点中；
  4. **容器重新封装**：将修改后的 XML 写回 ZIP 结构，生成全新的 `.docx` 字节流。
- **效果**：字体、字号、加粗、文字颜色、段落对齐、高阶表格排版 100% 完美无损保留。

```text
[段落 <w:p>]
  ├── Run 1: <w:t>法定代表人：张</w:t>
  └── Run 2: <w:t>建国 先生</w:t>
        │
        ▼ (内存投影合并为完整字符串)
"法定代表人：张建国 先生"  ──►  命中敏感词「张建国」
        │
        ▼ (按字符区间精确回写节点)
  ├── Run 1: <w:t>法定代表人：张</w:t>  ──► 改为: <w:t>法定代表人：*</w:t>
  └── Run 2: <w:t>建国 先生</w:t>        ──► 改为: <w:t>** 先生</w:t>
```

### 3.2 现代 XLSX / PPTX 原生脱敏

1. **XLSX 电子表格**：
   - 读取并解析 `xl/sharedStrings.xml`（共享字符串池）与各 `xl/worksheets/sheet*.xml`（行内字符串 `inlineStr`）；
   - 对字符串池中的文本统一检索并打码，单元格内的公式计算结果若涉及敏感原词同步脱敏；
   - 写回并打包输出原生 `.xlsx`。
2. **PPTX 演示文稿**：
   - 遍历 `ppt/slides/slide*.xml` 中的文本框节点（`<a:p>` 下的 `<a:r>` -> `<a:t>`）；
   - 应用与 DOCX 相同的跨 Run 投影算法打码，保留全部幻灯片母版、排版构图与动画效果。

### 3.4 纯文本类与原生 PDF 版式文档脱敏架构

```text
┌────────────────────────────────────────────────────────┐
│               原生矢量 / 文字类 PDF 文档               │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼ (lopdf 纯 Rust 流式解析引擎)
┌────────────────────────────────────────────────────────┐
│             PDF 对象树与 Content Stream 解码            │
│   ├── 解密并解压 /Contents (FlateDecode)               │
│   └── 解析为操作符流：BT ➔ /F1 12 Tf ➔ Tm ➔ Tj/TJ ➔ ET │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼ (Unicode 对齐 + 敏感词滑动窗口检索与等长掩码)
┌────────────────────────────────────────────────────────┐
│               字符流真脱敏（True Sanitization）         │
│   ├── 1. 命中的 Tj / TJ 算子就地等长打码 (WinAnsi/UTF-16)│
│   ├── 2. 擦除底层敏感字符绘制，杜绝 Ctrl+A 复制泄密    │
│   └── 3. 清理全局 /Metadata (XMP) 与 /Annots 批注      │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼ (Content::encode + 重新打包)
┌────────────────────────────────────────────────────────┐
│              输出脱敏后的标准原生 PDF 文档              │
│   - 100% 保留原生矢量排版、字体矩阵与版式视觉          │
│   - 纯 Rust 处理，单页耗时 < 10ms，零外部 C/C++ 依赖   │
└────────────────────────────────────────────────────────┘
```

- **纯文本（TXT / MD / CSV / JSON）**：
  - 直接在 UTF-8 字符流中基于字符偏移量（Offset）与原词快速打码（如首尾保留+中间掩码，或全掩码）；
  - CSV 严格遵循 RFC 4180 规范，输出 UTF-8 BOM 防 Excel 打开乱码。
- **原生 PDF 版式文档（非图片型）**：
  - 基于纯 Rust 的 `lopdf` 引擎，解析 Page `/Contents` 中的 `Tj` / `TJ` 文字绘制指令；
  - 精准定位并就地等长打码替换底层字符流，彻底物理抹除敏感信息；
  - 自动清理全局 `/Metadata`（XMP 元数据）与批注；
  > [!NOTE]
  > **边界说明**：当前阶段聚焦原生矢量/文字类 PDF 文档的真脱敏。扫描件与纯图片型 PDF 的 OCR 像素级光栅化遮盖作为后续版本迭代任务。

## 5. 后端 API 接口与数据契约全集 (v2)

### 5.1 核心 RESTful API 概览

| Method | Endpoint | 职责与描述 |
| :--- | :--- | :--- |
| `POST` | `/api/documents/upload` | 上传文档并持久化原始 buffer，异步触发 `anydoc` 转 Markdown |
| `GET` | `/api/documents` | 获取文档列表、字符数、快照摘要与最新状态 |
| `DELETE`| `/api/documents/{id}` | 删除指定文档及其历史全部快照，优雅回退工作区 |
| `POST` | `/api/extract` | 执行敏感信息提取（支持离线 `offline:` 与在线 `online:` 双轨） |
| `DELETE`| `/api/documents/{id}/snapshot/{snap_id}` | 删除单个历史快照 |
| **`POST`** | **`/api/documents/{id}/desensitize`** | **执行原生文档脱敏并流式下载（`mode: "native" \| "markdown"`）** |
| `GET` | `/api/models/presets` | 主动探测 `18188` 端口并返回离线模型列表 |
| `POST` | `/api/models/{filename}/start` | 动态拉起指定离线模型，监听专属端口 `18188` |
| `POST` | `/api/models/stop` | 精准杀掉当前子进程并释放 `18188` 孤儿端口 |
| `GET/POST`| `/api/settings/online-models` | 获取与保存在线 OpenAI 兼容 API 档案 |
