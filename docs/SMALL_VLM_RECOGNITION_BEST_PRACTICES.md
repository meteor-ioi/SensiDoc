# 小微端侧多模态模型 (VLM 0.8B~2B) 单据识别与结构化提取工程实践指南

> 本指南基于 SensiDoc 在真实高密财务单据（33 行复合表格、多单号、手写签批）场景下的攻坚实践，针对 Qwen3.5-0.8B、MiniCPM-2B 等轻量端侧视觉与语言模型在多模态排版重构、微切片局部纠偏中遭遇的**自回归死循环**、**微切片坐标越界侵入相邻列**、**复合列错位挤占导致核心单号丢失**等典型问题，总结出一套经过完整验证的工程避坑指南与最佳实践。

## 一、小微端侧模型在单据处理中的物理局限性

在构建端侧离线 AI 文档处理系统时，0.8B ~ 2B 级别的小微模型具备极佳的免配置、纯 CPU/核显可跑、毫秒级启动等优势，但相较于云端 70B+ 大模型，其存在三大固有的物理局限：

1. **工作记忆（Working Memory）与注意力跨度狭窄**：
   - 面对整页大图或长篇 Markdown 时，无法像大模型一样在几十个行和列之间进行全局交叉注意力对齐；
   - 极易受相邻区域字符干扰，发生“注意力漂移”。
2. **缺乏空间自适应剪裁感知**：
   - 如果切片边界给错或纵横比失衡，小模型无法自行脑补“切片切多了”，而是会将切片内所有的边缘文字（哪怕属于邻行或邻列）一并读出。
3. **极易陷入自回归重复死循环（Repetition Loop）**：
   - 当提示词与切片图像存在语义冲突、或切片过于模糊/仅有单个孤立字符时，小模型在生成阶段的 Token 概率分布会发生坍缩，自回归机制会不断输出前一个 Token（例如重复生成单号），直至打满 `max_tokens`。

## 二、四大黄金工程准则

### 准则 1：物理坐标语义与微切片裁剪隔离准则 (Spatial Isolation)

```
[错误做法] 混淆 coords 语义，计算 x1 = x + w (导致 min_x + max_x 坐标爆炸)
             ├── 纵向：15px 高度暴增至 600px，吃入整页十几行数据
             └── 横向：200px 宽度暴增至 500px，把右侧采购单号全切入左侧单元格

[正确做法] 严格按 [min_x, min_y, max_x, max_y] 计算:
             ├── 宽度 w = max_x - min_x, 高度 h = max_y - min_y
             ├── 垂直 pad_y = max(h * 0.15, 2.0)
             └── 水平 pad_x = max(h * 0.4, 6.0)  <-- 严格受字高约束，防止横向侵入相邻列
```

* **统一四元组坐标语义**：在整个数据流转管道中，强制统一使用 `[min_x, min_y, max_x, max_y]`，杜绝与 `[x, y, w, h]` 混用导致的乘积级长宽暴增。
* **紧致水平外扩**：表格单元格在横向往往紧密相邻，水平外扩 `pad_x` 绝不能按整词宽度比例扩展，必须由字高 `h` 严格兜底（如 `max(h * 0.4, 6.0)` 像素），杜绝切片吃进右侧相邻列。
* **物理行间距合并约束**：OCR 低置信度碎片在聚合成整词/整单元格时，只有在**物理垂直行间距相近（$\Delta Y < 40\text{px}$）**且同属于一个单元格上下文时才允许坐标合并，严禁跨行粗暴合并。

### 准则 2：短字符全文检索与全局替换熔断准则 (Fuzzy Match & Replace Guard)

* **单字符全文搜索熔断**：单字符或纯符号（如金额列被误识别的单个字母 `'S'`、`'$'`、`'-'` 等）**绝对禁止**在 Markdown 正文中进行全局模糊检索（如 `contains(clean)`）。
  * 案例：单据金额列误识的单字母 `'S'`，因全局搜索直接命中了第 1 行标题 `SUPERL.(CAMBODIA) CO..LTD.`，导致标题被错误替换为死循环字符串。
* **单字符噪声过滤**：送入 VLM 智能复核的低置信度碎片，必须满足有效字符数 $\ge 2$。孤立单字符通常为 OCR 底噪或污迹，单独切片复核极易诱发幻觉。
* **单元格级精准替换与长度围栏**：
  * 替换时优先采用完整单元格替换，若退化到文本替换，目标词长度必须 $\ge 3$ 个字符；
  * 模型返回的纠正文本必须通过长度安全校验：$\text{len} \le \max(3 \times \text{orig\_len}, 60)$。一旦模型产生幻觉吐出数百字长串，立即触发熔断拒绝替换。

### 准则 3：小微模型防死循环超参数配置准则 (Anti-Loop Hyperparameters)

对于微切片纠偏或短语级识别任务，必须在推理请求层配置严密的防死循环屏障：

```json
{
  "temperature": 0.0,
  "max_tokens": 128,
  "repetition_penalty": 1.15,
  "frequency_penalty": 0.3,
  "presence_penalty": 0.2
}
```

* **物理截断 `max_tokens`**：微切片纠偏输出目标通常仅为 1~10 个单词，将 `max_tokens` 从传统的 1024 强力收敛至 **64 ~ 128**，在物理层面彻底掐死千字死循环通道。
* **零采样温度 `temperature: 0.0`**：消除随机性，促使模型严格按最高概率 Token 贪婪解码，提升输出确定性与原文字符还原率。
* **双重惩罚因子**：同时引入 `repetition_penalty`（比率压制）与 `frequency_penalty`（出现频次惩罚），从底层 Logits 阶段抑制循环输出。

### 准则 4：全量高密表格重构：提示词显式解耦复合列（避免强行注入 OCR 文本导致错字污染）

在多模态工程中，开发者常倾向于将 OCR 文本注入到 Prompt 中作为参考。但**真实盲测发现致命缺陷**：
> **文本先验偏见（Text Prior Bias）**：0.8B~2B 小模型的跨模态注意力较弱，一旦 Prompt 中存在现成文本，模型在生成时倾向于直接“抄文本”，完全丧失视觉纠错能力！
> - **实测证据**：原图金额为 `$ 10.51`，基础 OCR 误识为 `10.5f`。若注入 OCR 文本，全量 VLM 输出直接被带偏为 `10.5f`，且将 OCR 的乱码 `PALOGISHCSCO HP.` 一并照抄！

```
[原单据首列特征]  "1  CHAY DA LOGISTICS CO., LTD." (序号 + 公司名复合排版)
      │
      ▼ (原版通用 Prompt: "转换为 Markdown 表格")
[错位挤占丢单号]  模型将序号算作第 1 列、公司名算作第 2 列，导致真正第 2 列采购单号被挤掉！
      │
      ▼ (全新工程方案：提示词显式解耦复合列 + 纯视觉高清输入)
[100% 零错字重构]  声明首列同时包含序号与公司名，第 2 列为纯单号。
                 模型纯看图识别出高精度 $ 10.51 与 LOGISTICS，完全摆脱 OCR 污染！
```

#### 系统提示词黄金模板（100% 通用无业务硬编码）：
```text
你是一名顶级多模态单据与复杂文档高保真结构化排版专家。请仔细观察单据图像，高保真重构为排版工整、结构严谨的标准 Markdown 格式。

【通用排版准则】：
1. 【复合单据分表解耦】：单据顶部抬头、核心明细大表、汇总/账户信息、底部审批签名栏必须分为独立的 Markdown 段落或各自独立的 Markdown 表格，严禁跨区域强行合并为单一大表；
2. 【核心数据项零丢失与防挤占】：
   - 单据表格中的所有数据项（如序号、项目/商品描述、发票号/采购单号/编码、币种/单位、数量、单价、金额）必须 100% 完整保留在表格中，严禁遗漏任何一列数据；
   - 【防挤占与列对齐】：当表格首列包含序号与描述时，严禁让描述文本挤占后续的关键单号/编码列！你可以将序号与描述合并在同一单元格（如 `1 描述文本`），或规范拆分为【序号】与【描述】独立两列，但单号/编码必须独立保留在对应列中，绝不能因排版挤压导致单号被吞；
   - 核心表格存在多行明细时必须逐行全部输出，严禁擅自省略；
3. 【底部审批与签批栏通用规范 (防虚构人名与防行列错位)】：
   - 【防人名脑补与空白如实还原】：对于各类单据底部的签字、盖章、审核栏，若包含不可精确辨识的草书或手写签名，统一标注为 [手写签名]；若单元格/区域完全空白无笔迹，必须如实标注为 [未签署/空白]，绝对严禁凭空臆造、联想或生成任何虚构人名与拼音；
   - 【结构化列表解耦】：审批签名栏统一使用键值列表排版（格式如 `- **角色名称:** [签署状态] (签署日期)`），中英文对照角色标签保持在同一项，严禁拆开；
   - 【日期归属】：签署日期必须紧随对应的签署角色，严禁将各格底部的日期抽出作为独立的数据行输出；
4. 层次清晰分明，标题使用 # / ## 标记，直接流式输出 Markdown 正文，绝对禁止包含任何解释说明或 ```markdown 等代码块标记。
```
